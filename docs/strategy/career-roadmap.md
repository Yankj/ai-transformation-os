# Career roadmap

## Transition ladder

| Horizon | Target role | Proof of capability | Current emphasis |
| --- | --- | --- | --- |
| 0–2 weeks | AI Application Engineer | Can explain and build an Agent Runtime vertical slice | Agent loop, tool boundary, trace, evaluation |
| 1 month | AI Platform Engineer | Can design reusable Agent, Workflow, Knowledge, Tool, Runtime, Evaluation, and Engineering capabilities | Platform capability map and interfaces |
| 3–12 months | AI Solution Architect | Can shape an AI-native system and its operating model for a real business context | Reference architecture, trade-offs, case studies |
| Ongoing | AI Native Builder | Sustains products, methods, community, and commercial value | Reusable IP and distribution flywheel |

## Capability map

```text
Experience layer
  └─ AI application / workflow UX
Intelligence layer
  └─ agents, prompts, planning, memory, knowledge
Platform layer
  └─ tools, runtime, workflow, observability, evaluation, governance
Engineering layer
  └─ delivery, testing, security, cost, developer experience
Business layer
  └─ discovery, value metrics, adoption, commercialisation
```

The immediate work begins at the runtime boundary, but each experiment should
make explicit which layer it touches. This prevents becoming a framework-only
agent developer.

## Founder leverage

| Existing strength | AI-platform translation |
| --- | --- |
| Frontend architecture | Human-in-the-loop, AI application UX, streaming interaction |
| Component/platform design | Reusable agent/tool/workflow contracts and SDKs |
| Engineering effectiveness | Eval pipelines, observability, CI, developer experience |
| Large-company delivery | Governance, reliability, integration, adoption |

## Milestone evidence

Role labels are not the target; evidence is. Each horizon is only complete
when it has a demonstrable project, decision record, evaluation evidence, and
an explanation another engineer can learn from.
