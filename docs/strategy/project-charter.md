# Project charter

## Problem

Experienced software engineers often consume AI material without accumulating
credible, reusable evidence of capability. Notes stay isolated, demos become
disposable, and publishing is disconnected from practice. This makes a career
transition look like a collection of courses instead of an operating system.

## Product thesis

ATOS converts a practitioner's real work into a flywheel:

```text
Question → knowledge asset → experiment/demo → evidence → content/portfolio
        ↑                                                  ↓
        └──────────── review, feedback, and product insight ┘
```

Each pass should improve both the practitioner and the system another
practitioner could eventually follow.

## Audience sequence

1. **Founder:** a senior frontend/platform engineer moving into enterprise AI.
2. **Peers:** experienced software engineers seeking an AI transition path.
3. **Teams:** engineering organisations adopting AI-native ways of working.

The first audience has priority. Prematurely designing for everyone is the
largest threat to this MVP.

## Strategic positioning

ATOS is not a generic AI course. It differentiates through an engineering-led
view of AI: runtime contracts, tools, workflow, knowledge, evaluation,
reliability, and developer experience. Existing frontend platform and
engineering-productivity experience is an advantage, not a detour.

## Asset model

| Asset | Created by | Later becomes |
| --- | --- | --- |
| Knowledge card | Learning/research | Guide, lesson, reference architecture |
| Experiment report | Practice | Case study, benchmark, consulting proof |
| Demo | Engineering | Portfolio, workshop, product seed |
| Content brief | Synthesis | Article, talk, video, newsletter |
| Review | Reflection | Improved playbook, roadmap signal |

## Non-goals for MVP-01

- Building a complete AI platform.
- Supporting every agent framework or model provider.
- Publishing at high frequency before the work has evidence.
- Selling a course before a repeatable result exists.

## Success principle

The MVP succeeds when its loop is repeatable and truthful—not when the
repository has the most files or the demo has the most features.
